# 아이템 등급(Grade) 스탯 스케일링 기획서

> 상태: 기획 (개발 전) · 작성일: 2026-06-15 · 대상: AzerothCore WotLK 3.3.5a

---

## 1. 목표

- 모든 플레이어가 **같은 베이스 아이템**(동일 `itemEntry`)을 드랍한다.
- 단, 드랍되는 **인스턴스마다 품질 등급(S~D)** 이 부여되어, `item_template`에
  정의된 **기본 옵션값(스탯)** 을 등급별 배수로 **가감(+/-)** 한다.
- **S등급 = 기본보다 가장 좋은 옵션 / 확률 최저.** D등급 = 기본보다 낮은 옵션.

---

## 2. 확정된 설계 방향 (요약)

| 항목 | 결정 |
|------|------|
| 기본 구조 | **접근 A** — 서버 능력치 스케일링(코어 훅에서 기본옵션 ×배수) |
| item_template | **새 행 추가하지 않음** |
| 적용 스탯 범위 | **스탯(`ItemStat[]`) 한정** (방어구/무기데미지/Block/저항 제외) |
| 등급 방향 | **+등급과 −등급 모두 존재** |
| 적용 대상 | 스탯 장비(`StatsCount>0`). **세트(티어) 포함**, 퀘스트 아이템만 제외 |
| 획득 경로 | **몬스터(크리처) + 상자/오브젝트(GameObject) 드랍**. 상점/제작/퀘보상/우편 제외 |
| 표시(툴팁) | **코어 훅 + 커스텀 애드온**(방법 ①)으로 정확 표시. 기존 인챈트/접미사 시스템과 역할 분리 |
| 등급 저장 | **별도 테이블 `mod_item_grade(item_guid, grade)`** (몬스터 드랍 시 롤·저장, 코어/스키마 무수정). 자동 생성 |
| 강화/마부 호환 | 마부·GUID유지강화=등급 유지. **karazhan(GUID교체형) 강화는 재생성 시 등급 이전** |
| 보관·이동 보존 | 장비는 스택 불가 → 개인금고·길드금고·거래·우편에서 **등급 완전 보존** |

> 구현 완료(2026-06-15): `modules/mod-item-grade` + 클라 애드온 `ItemGrade` +
> `mod-item-karazhan` 연동(등급 이전). 빌드/인게임 테스트는 별도.

## 3. 기본 구조: 접근 A (서버 능력치 스케일링)

`item_template`에 **새 행을 추가하지 않고**, 기본 옵션값을 캐릭터 능력치에
적용하는 지점에서 등급 배수를 곱한다.

- 적용 지점: `Player::_ApplyItemBonuses()` 내부의 기존 훅
  `OnPlayerApplyItemModsBefore(player, slot, apply, statIndex, statType, val)`
  - 파일: `src/server/game/Entities/Player/Player.cpp:6668`
  - `val`(= `proto->ItemStat[i].ItemStatValue`)이 **참조(int32&)** 로 전달됨
    → 모듈에서 `val = round(val * 등급배수)` 로 변경하면 기본 옵션값이 그대로 ±됨.
- 코어 수정 최소(순수 모듈로도 가능), `item_template` 스키마 무변경.
- **적용 범위: 스탯(`ItemStat[]`) 한정.** 방어구/무기데미지/방패Block/저항은
  이 훅이 커버하지 않으므로 등급 적용 대상이 아니다(합의됨).

### 3.1 대칭성 원칙 (필수)

`_ApplyItemBonuses` 는 장착 시 `apply=true`(가산), 해제 시 `apply=false`(감산)으로
**두 번 호출**되며, 두 시점의 `val` 이 **반드시 동일**해야 한다. 아니면 능력치가
영구 오염된다. → 등급은 **인스턴스마다 고정값**이어야 한다(§5).

## 4. 표시(Display): 코어 훅 + 애드온 (방법 ①)

### 4.1 왜 애드온이 필요한가

3.3.5 클라이언트는 아이템 **이름·기본 스탯 숫자를 `itemEntry` 단위로 캐싱**해
그린다(`CMSG_ITEM_QUERY_SINGLE` 1회 질의 후 재사용). 따라서 **서버만 고쳐서는**
인스턴스별로 다른 숫자를 기본 툴팁에 표시할 수 없다.

### 4.2 채택: 코어 훅(스탯) + 커스텀 애드온(표시)

- **코어 측(소규모)**: 인스턴스의 등급값을 클라로 전달
  (애드온 메시지 `SendAddonMessage`, 또는 per-instance 필드에 실어 전송).
- **클라 측(애드온만)**: `GameTooltip` / `ItemRefTooltip` 의 `OnTooltipSetItem`
  훅에서 기본 스탯 줄을 읽어 **등급 배수를 곱해 숫자를 다시 출력**.
- 결과: **기본 스탯 정확한 ×배수 표시 + 단일 엔트리 유지 + item_template 무추가 +
  클라 바이너리 무패치.** ✅
- 한계: **애드온 설치자에게만** 정확히 보임(미설치자는 기본값 툴팁).

### 4.3 기존 시스템과의 관계 (중요)

운영 중인 **인챈트/접미사 기반 시스템(접근 B)** 은 표시/연출 용도로 이미 사용 중이므로
**중복 개발하지 않는다.** 역할 분리 원칙:

- **실제 스탯 증감** = 접근 A(코어 훅)가 단독 담당.
- **등급 라벨/연출** = 기존 시스템 또는 애드온이 담당.
- ⚠️ **이중 계산 금지**: 기존 시스템이 스탯을 추가 부여하는 방식이면, 접근 A의
  스케일링과 합산되어 과다 적용되지 않도록 한 쪽만 실제 스탯에 관여하게 한다.

### 4.4 대안: 클라 바이너리 패치 (방법 ②)

WoW.exe 툴팁 렌더 함수를 직접 패치하면 **애드온 없이 전 플레이어에게 네이티브
표시** 가능. 단 리버싱·바이너리패치·커스텀 클라 배포·유지보수 부담이 커서
"일부 수정" 범위를 벗어난다. **전원 네이티브 표시가 반드시 필요할 때만** 채택.

| 요구 | 코어 훅만 | +애드온 ① (채택) | +바이너리패치 ② |
|------|:---:|:---:|:---:|
| 기본옵션 정확한 ±배수 | ✅ | ✅ | ✅ |
| item_template 무추가 | ✅ | ✅ | ✅ |
| 툴팁 정확 표시 | ❌ | ✅(설치자) | ✅(전원) |
| 클라 배포 부담 | 없음 | 애드온만 | exe/런처 |
| 난이도 | 낮음 | 중 | 높음 |

## 5. 등급 결정 및 저장

### 5.1 등급 모델 (최종, 2026-06-17)

D 가 기본(±0%)이며 한 단계 오를 때마다 +2%. **음수(−) 등급 없음.**

| 등급 | 옵션 배수 | 드랍 확률 | 색상 |
|------|-----------|-----------|------|
| S    | ×1.08 (+8%) | 1%  | 주황 ★ |
| A    | ×1.06 (+6%) | 6%  | 보라 |
| B    | ×1.04 (+4%) | 13% | 파랑 |
| C    | ×1.02 (+2%) | 30% | 초록 |
| D    | ×1.00 (±0%) | 50% | 흰색(기본) |

- 배수·확률은 **config(`.conf.dist`)** 로 조정 가능.
- 라운딩: 반올림. 양수 옵션은 최소 1 보장.
- **기본 등급(D, ×1.0)** 은 획득 채팅 알림을 생략(도배 방지)하나 **툴팁에는 표시**됨.

### 5.2 방식 1 — GUID 결정론적 산출 (권장)

- `grade = 확률표매핑( mix(item->GetGUID().GetCounter()) % 10000 )`
- 별도 저장 없음 → **DB 컬럼/테이블/스키마 변경 전혀 불필요**, 순수 모듈.
- GUID는 드랍(아이템 생성) 시 확정되어 영구 불변 → 등급도 영구 고정, 대칭성 보장.
- 주의: GUID 카운터는 **순차 증가**라 단순 `% 100` 은 분포 치우침
  → splitmix/xorshift 류 **해시 믹싱 후** 버킷팅.

### 5.3 방식 2 — item_instance 컬럼 저장 (대안)

- `item_instance` 에 `grade TINYINT` 추가 + `Item` 멤버 + `SaveToDB`/`LoadFromDB` 수정.
- 드랍 시 1회 롤(`rand_chance`/`urand`)해 저장. GM 수동 지정·재롤·조회 용이.
- `item_template` 은 여전히 무변경(요구 충족). characters DB 스키마만 확장.
- 방식 1보다 제어력↑, 구현량↑.

> 권장: **방식 1**로 시작, "특정 아이템 등급 수동 부여/재롤" 또는 "드랍 한정 엄격
> 적용"(§6) 요구가 생기면 **방식 2**로 확장.

## 6. 적용 대상 / 제외 군

> 최종 확정은 §11.5 참조(세트 포함, 상자/오브젝트 포함으로 확장됨).

- 적용: **스탯을 가진(`StatsCount > 0`) 장비**.
- 제외:
  - **퀘스트 아이템**: `class == ITEM_CLASS_QUEST` → 제외.
  - 스탯 없는 아이템(잡템/소비/재료)은 자연히 대상 외.
- 세트(티어) 아이템: **포함**(세트 보너스 자체는 스케일 대상 아님, 각 부위 +스탯만 스케일).

### 6.1 "드랍만" 정책의 엄밀도 (미결 — §9)

- **방식 1(GUID)** 은 출처(드랍/제작/상점)를 구분하지 못하므로, 사실상
  **모든 대상 장비**에 등급이 매겨진다. "기존 보유분/비드랍템은 기본(B) 취급"을
  엄격히 지키려면 **방식 2 + 드랍 시점에만 롤·저장**이 필요하다.
- 운영 정책으로 "전 장비 일괄 적용 허용"을 택하면 방식 1로 충분.

## 7. 보관·이동 시 등급 보존 (분석 완료)

### 7.1 결론: 장비는 어디에 보관해도 등급 완전 보존

개인 은행·길드금고에 보관해도 아이템은 **새로 생성되지 않고 동일 GUID·동일
`item_instance` 행** 을 유지한다(위치 정보만 변경).

- `character_inventory`(개인) / `guild_bank_item`(길드금고) 는 **슬롯 위치만**
  기록하고, 실제 데이터는 `item_instance` 행을 `item_guid`로 **참조**.
- 길드금고 보관 시 `owner_guid`만 0으로 바뀌고, `enchantments`·`randomPropertyId`·
  `durability` 등 per-instance 필드는 **그대로 유지**.
  ([Guild.cpp:473 `BankTab::SetItem`](src/server/game/Guilds/Guild.cpp))

| 저장 방식 | 보존 원리 |
|-----------|-----------|
| 방식 1 (GUID) | 등급 = f(GUID). 이동해도 GUID 불변, owner_guid 변경 무영향 → 자동 유지 ✅ |
| 방식 2 (컬럼) | 컬럼이 item_instance 행에 있고 그 행이 유지됨 → 유지 ✅ |

→ 개인금고·길드금고·거래·우편 모두 등급 보존. 두 방식 다 안전.

### 7.2 유일한 함정: 스택 분할 — 단, 장비엔 미발생

per-instance 필드가 깨지는 경우는 **스택 분할(split)** 뿐. 이때
`Item::CloneItem()`이 **새 GUID**로 복제하며 enchantments/durability 등을 복사하지
않는다([Item.cpp:1118](src/server/game/Entities/Item/Item.cpp)).

- 방식 1: 복제본은 새 GUID → 다른 등급.
- 방식 2: `CloneItem`이 등급 컬럼도 복사 안 함 → 복제본 등급 소실.

**그러나 등급 대상은 "스탯 장비"이고 장비는 스택 불가** → 분할·스택병합 자체가
일어나지 않음 → 이 함정은 **본 기획에 해당 없음.**

> 안전장치(향후 확장 시): 등급을 스택 아이템으로 확장한다면 `Item::CloneItem()`에
> 등급 복사 로직을 추가하면 분할 시에도 보존된다. 현 장비 한정 기획에서는 불필요.

## 11. 구현 확정 사항 (2026-06-15)

기획 §9 미결정 사항이 다음과 같이 확정되어 구현되었다.

### 11.1 최종 설계

- **등급 부여 시점**: 루팅(`OnPlayerLootItem`, `lootguid.IsCreature() ||
  IsGameObject()`) 시 1회 롤(`urand` 확률표) → 별도 테이블
  `mod_item_grade(item_guid, grade)` 저장. **모든 등급(B 포함) 저장·표시**
  (2026-06-16 변경: 모든 루팅 장비에 등급 라벨 표시). B 는 ×1.0 이라 스탯 변동 없음.
  단 획득 채팅 알림은 도배 방지를 위해 **비-B 등급만** 표시.
- **저장 위치**: 별도 테이블(코어/`item_instance` 스키마 무수정). 서버 기동 시
  `CREATE TABLE IF NOT EXISTS` 로 자동 생성, 전량 메모리 캐시 로드.
- **스케일**: `OnPlayerApplyItemModsBefore` 에서 저장 등급 조회 → 배수 적용.
  저장 등급이 없으면 스케일 안 함(= 비-루팅 획득 아이템은 영향 없음).
- **표시**: 등급 정보를 클라 좌표(가방/슬롯)별로 애드온(`IGRADE`)에 푸시 →
  애드온이 툴팁에 등급 라벨 + 스케일 수치 표시.
- **정리**: `OnItemDelFromDB` 에서 삭제 아이템의 등급 행 제거(고아행 방지).

### 11.2 전수 점검 — 등급을 가진 장비의 GUID 변경 경로

| 경우 | GUID | 처리 |
|------|------|------|
| 거래/우편/은행/길드금고/장착·해제 | 불변 | 등급 유지 |
| 마부(인챈트)/보석 | 불변 | 등급 유지 (별도 경로) |
| mod-custom-changes 강화(플랫 보너스) | 불변 | 등급 유지 |
| **mod-item-karazhan 강화 성공** | **변경(새 아이템 1곳, 라인 1127)** | **등급 이전 코드 적용** |
| 스택 분할(CloneItem) | 변경 | 장비는 스택 불가 → 해당 없음 |
| 블랙마켓/아레나 구매·드랍 | 변경(새 아이템) | 몬스터 드랍이 아니면 등급 미부여(정상) |

- **GUID 재사용 없음**(카운터 단조증가, 소진 시 서버 정지) → stale 등급이 새
  아이템에 오적용될 위험 없음. 삭제 정리는 테이블 비대화 방지용.
- karazhan 연동: 재생성 직후 `ItemGradeBridge::OnItemRecreated(old, new)` 호출
  (ItemKarazhan.cpp 라인 1187 부근). `ApplyRandomProperty()`(라인 546)는 미호출
  죽은 코드라 대상 아님.

### 11.3 통합 충돌 점검 결과 (다른 컨텐츠와의 혼선)

| 점검 항목 | 결과 |
|-----------|------|
| 애드온 prefix 충돌 | 없음. `IGRADE` vs 타 모듈 `KARAZHAN_*` 로 분리 |
| 다른 OnPlayerLootItem 사용(transmog 수집, eluna) | 독립 동작, 간섭 없음 |
| 다른 OnPlayerApplyItemModsBefore 사용(custom-changes) | custom-changes는 훅 미등록이라 미작동 → 무관. 설령 작동해도 `val` 을 안 만지고 별도 플랫 보너스라 충돌 없음 |
| 스탯 읽기 불일치 | template(proto)은 불변, 적용값만 변경 → template 읽는 모듈과 데이터 일관성 유지(단 BlueItemInfo3 등 클라 표시 애드온은 기본값 표시) |
| karazhan 강화 이중적용 | 없음. karazhan은 enchant/randomProperty 경로(별도), 등급은 base ItemStat 스케일 |
| **캐릭터 삭제 시 고아행** | 코어가 raw SQL 일괄삭제로 `OnItemDelFromDB` 미발동 → **서버 기동 시 anti-join 으로 고아행 자동 청소**(보강 적용) |

- **남은 주의**: Eluna(mod-ale) 등에서 **Lua 스크립트가 아이템을 재생성**(새 GUID)하는
  커스텀 로직이 있다면 등급이 이전되지 않는다. 그런 스크립트가 있으면 해당 지점에서
  `ItemGradeBridge::OnItemRecreated` 에 해당하는 처리를 추가해야 한다.

### 11.4 클라이언트 애드온 호환 점검 결과

- **설치 애드온**(Bagnon / BlueItemInfo3 / AzerothAdmin / karazhan): 충돌·크래시·
  이중적용 없음.
  - Bagnon: 내 가방 살아있는 아이템은 `ContainerFrameItemButton_OnEnter → SetBagItem`

  - karazhan ItemEnhancement 툴팁: 별개 줄(강화레벨 vs 등급) 추가로 공존. 우리 스탯
    재계산은 흰색 기본 스탯 줄만 대상이라 karazhan 의 색 있는 줄은 건드리지 않음.
  - BlueItemInfo3: `AddLine`만 사용(스탯 줄 미재작성) → 충돌 없음.
  - AzerothAdmin: 빈 prefix 사용, 우리는 `IGRADE` 만 수신 → 충돌 없음.
- **통합애드온(ElvUI/TukUI/Pawn/TipTac 등, 플레이어 임의 설치)**: 구조상
  - 서버측 스탯 스케일은 애드온 독립 → 충돌 불가, 전원 동일 적용.
  - ItemGrade 애드온은 `hooksecurefunc` 안전 후킹 → 타 애드온 미파손.
  - **확정 결정(2026-06-15)**: Pawn/RatingBuster/GearScore 등 **아이템 점수
    평가 애드온이 등급을 인식하지 못하는 것은 수용**한다(템플릿 기본수치 기준).
    서버 능력치 정확 적용 + ItemGrade 애드온 표시로 충분하다고 확정.

### 11.5 적용 범위 확장 (2026-06-16)

- **루팅 출처**: 몬스터(크리처)뿐 아니라 **상자/오브젝트(GameObject) 드랍 포함**.
  (`lootguid.IsCreature() || lootguid.IsGameObject()`)
- **세트(티어) 아이템 포함**: 기존 `ItemSet != 0` 제외 규칙 삭제. 각 부위의
  `+스탯`만 등급 배수 적용되며, **세트 보너스(착용 N개 효과)는 스케일 대상이 아님**.
- 변함없이 **퀘스트 아이템·무스탯 아이템·비-루팅 획득(상점/제작/퀘보상/우편)** 은 제외.
- 표시 동기화 보강: 슬롯 매핑 어긋남 방지를 위해 인벤토리 변화 주기 감지
  (`ItemGrade.SyncIntervalMs`, 기본 1초) + 로그인/장착/획득/이동 시 즉시 재전송.
- 색상: 회색 제거, 등급별 선명 색(S 주황+★ / A 보라 / C 하늘 / D 빨강).

### 11.6 전 품질 표시 + 접미사 스케일 + 귓속말 (2026-06-16)

- **모든 등급(B 포함) 저장·표시**: B(50%)가 안 보여 "간헐적"으로 느껴지던 문제 해결.
  모든 루팅 장비에 S/A/B/C/D 라벨 표시. B 는 `등급: B (기본)`, ×1.0.
- **대상 확대**: `StatsCount>0` 조건 제거 → **모든 무기/방어구**(흰/회/초록/파랑/
  보라/주황) 대상. (`Class == WEAPON || ARMOR`)
- **접미사 스케일 추가**: 초록 "곰의~" 등은 기본 스탯이 0이고 옵션이 랜덤
  접미사(인챈트)로 들어감 → `OnPlayerApplyEnchantmentItemModsBefore` 의 PROP
  슬롯(7~)만 등급 배수 적용. 일반 마부·보석은 제외. 애드온도 초록색 "+N" 줄을
  재계산하도록 색 필터 제거.
- **획득 알림 귓속말화**: 시스템 메시지 → `CHAT_MSG_WHISPER`(본인 세션에만 전송).
- **남은 한계**: 방어구 수치/무기 데미지만 있는 무스탯 아이템은 라벨은 보이나
  수치 변동 없음(Armor/DPS 스케일은 별도 코어 패치 필요).

### 11.7 등급표 개편 + 컨테이너 루팅 포함 (2026-06-17)

- **"등급 누락" 오해 해소**: 기본 등급은 채팅 알림을 안 보내서 "등급 없음"으로 보였던
  것일 뿐, 툴팁에는 모든 장비에 등급이 표시되고 있었음.
- **등급표 개편**: 기본을 **D(±0%)** 로, 한 단계 오를 때마다 **+2%**.
  음수(−) 등급 제거. (D 1.00 / C 1.02 / B 1.04 / A 1.06 / S 1.08)
  - 확률(기본): D 50% / C 30% / B 13% / A 6% / S 1%.
  - 색상: D 흰 / C 초록 / B 파랑 / A 보라 / S 주황(★) — WoW 등급색 순.
  - 알림 제외 기준을 "특정 등급(B)"에서 **"배수 1.0(기본)"** 으로 변경 → D 는 알림 생략.
- **컨테이너 아이템 루팅 포함**: 보상 가방·자물쇠 상자 등을 열어 나온 장비(루팅
  출처 `IsItem`)도 등급 부여 대상에 추가. (`IsCreature() || IsGameObject() || IsItem()`)
