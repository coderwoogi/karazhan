# 영웅석 룬문자 지역 박스 드랍 기획안

## 검산 결과

DB 기준 룬문자 아이템 수량은 정상입니다.

| 항목 | 결과 |
|---|---:|
| `hero_stone_teleport_locations` 위치 수 | 231 |
| 고유 룬문자 아이템 수 | 231 |
| 룬문자 아이템 범위 | 950010 ~ 950240 |
| `item_template`에 존재하는 룬문자 아이템 수 | 231 |
| 지도별 그룹 수 | 66 |
| 지도별 그룹 합계 | 231 |

따라서 현재 룬문자 아이템 데이터는 총 231개가 맞습니다.

## 목표

각 지도/지역마다 룬문자 박스를 랜덤하게 배치하고, 해당 지도에 묶인 룬문자만 그 지역 박스에서 획득되도록 한다.

예시:

| 지도 | 해당 박스에서 나올 수 있는 룬문자 |
|---|---|
| 여명의 설원 | 여명의 설원에 묶인 룬문자 |
| 가시덤불 골짜기 | 그롬골 주둔지, 무법항, 구루바시 투기장, 줄구룹 등 |
| 북풍의 땅 | 북풍의 땅 마을, 마력의 탑, 영원의 눈 등 |
| 얼음왕관 | 얼음왕관 거점, 용사의 시험장, 십자군의 시험장, 얼음왕관 성채 등 |

## 핵심 설계

지역별로 별도의 박스 타입을 만든다.

같은 지역에 여러 개의 후보 좌표를 만들어두고, AzerothCore의 pool 시스템으로 그중 일부만 활성화한다. 이렇게 하면 서버 재시작 또는 pool 갱신 시 박스 위치가 랜덤하게 바뀐다.

박스를 클릭하면 일반 루팅 창이 열리는 것이 아니라 가십 메뉴가 열린다. 가십 메뉴에서 룬문자 확인/획득 버튼을 제공하고, 스크립트가 구독 상태와 계정 해금 상태를 확인한 뒤 지급 여부를 결정한다.

## 권장 구조

| 구성 | 역할 |
|---|---|
| `gameobject_template` | 지역별 룬문자 박스 타입 |
| `gameobject` | 박스 후보 스폰 좌표 |
| `pool_template` | 지역별 활성 박스 개수 제한 |
| `pool_gameobject` | 후보 박스 중 랜덤 활성화 |
| `hero_stone_teleport_locations` | 지역별 룬문자 아이템 매핑 원본 |
| 신규 매핑 테이블 | 박스 entry와 지역/룬문자 연결 |
| Lua 또는 C++ 스크립트 | 가십 메뉴 표시와 실제 룬문자 지급 조건 처리 |

## 루팅 방식 대신 가십 메뉴 방식을 사용

`gameobject_loot_template`만 사용하면 박스에서 아이템 드랍은 가능하다. 하지만 아래 조건을 처리하기 어렵다.

| 조건 | DB loot만으로 처리 가능 여부 |
|---|---|
| 이미 계정에 새겨진 룬문자 제외 | 어려움 |
| 구독자에게 룬문자 미지급 | 어려움 |
| 이미 가방에 같은 룬문자가 있으면 제외 | 어려움 |
| 지역별 드랍 확률 동적 조정 | 제한적 |
| 획득 로그 기록 | 어려움 |

따라서 박스는 `gameobject`로 배치하되, 사용 시 루팅이 아니라 가십 메뉴를 열고 Lua 또는 C++에서 지급 판정을 하는 방식이 더 안전합니다.

중복 보유는 허용한다. 즉, 이미 가방에 같은 룬문자 아이템이 있어도 추가 획득이 가능하다. 다만 이미 계정에 해금된 룬문자는 지급하지 않는다.

## 가십 메뉴 구성

박스를 클릭하면 아래와 같은 메뉴를 보여준다.

| 메뉴 | 설명 |
|---|---|
| 지역명 | `희미한 룬문자 상자 - 여명의 설원` 형식으로 표시 |
| 설명 | 이 지역에서 발견 가능한 룬문자 수와 획득 안내 |
| 룬문자 확인 | 획득 가능 여부와 확률 판정 실행 |
| 닫기 | 가십 종료 |

예시 문구:

```text
희미한 룬문자 상자 - 여명의 설원

이 상자에서는 여명의 설원 지역과 관련된 룬문자를 발견할 수 있습니다.
이미 영웅석에 새겨진 룬문자는 다시 발견되지 않습니다.
```

버튼:

```text
룬문자를 확인한다
닫기
```

## 권장 지급 흐름

```text
유저가 지역 룬문자 박스 클릭
        ↓
가십 메뉴 열림
        ↓
유저가 "룬문자를 확인한다" 선택
        ↓
박스 entry 또는 guid로 지역 그룹 확인
        ↓
구독자인지 확인
        ↓
해당 지역에 묶인 룬문자 목록 조회
        ↓
계정 기준 이미 해금된 룬문자 제외
        ↓
남은 후보 중 랜덤 1개 선택
        ↓
룬문자 아이템 지급 또는 우편 발송
        ↓
획득 로그 기록
        ↓
박스는 일정 시간 후 재스폰 또는 pool 갱신
```

## 박스 배치 수량 정책

지도별 룬문자 수에 따라 후보 박스 수와 실제 활성 박스 수를 다르게 둔다.

| 해당 지도 룬문자 수 | 후보 박스 수 | 동시 활성 박스 수 |
|---:|---:|---:|
| 1 ~ 2개 | 3개 | 1개 |
| 3 ~ 5개 | 5개 | 2개 |
| 6 ~ 9개 | 8개 | 3개 |
| 10개 이상 | 12개 | 4개 |

이 기준을 현재 66개 지도 그룹에 적용하면 다음과 같습니다.

| 항목 | 수량 |
|---|---:|
| 전체 지도 그룹 | 66 |
| 전체 룬문자 수 | 231 |
| 전체 후보 박스 수 | 315 |
| 전체 동시 활성 박스 수 | 112 |

즉, DB에는 후보 박스 315개를 배치하고, 실제로 월드에 동시에 보이는 박스는 112개 정도가 됩니다.

## 박스 위치 생성 기준

완전 랜덤 좌표는 사용하지 않는다. 벽 안, 하늘, 바다, 인스턴스 내부, 접근 불가능한 지형에 생성될 위험이 큽니다.

대신 아래 순서로 후보 좌표를 만든다.

1. 해당 지도에 묶인 `hero_stone_teleport_locations` 좌표를 기준점으로 사용한다.
2. 기준점에서 15~60미터 정도 떨어진 위치를 후보로 만든다.
3. 마을 한가운데, NPC 바로 옆, 포탈 바로 앞은 피한다.
4. 길가, 건물 뒤, 나무 근처, 폐허 주변처럼 유저가 찾을 수 있는 위치를 우선한다.
5. 도시 내부는 너무 노출되지 않도록 외곽이나 골목으로 보정한다.
6. 인던/공격대는 실제 인스턴스 내부가 아니라 입구가 있는 필드 지역에 배치한다.

## 신규 테이블 제안

### 지역 그룹 테이블

```sql
CREATE TABLE IF NOT EXISTS `hero_stone_rune_box_region` (
  `region_id` INT UNSIGNED NOT NULL AUTO_INCREMENT,
  `region_name` VARCHAR(80) NOT NULL,
  `box_entry` INT UNSIGNED NOT NULL,
  `pool_entry` INT UNSIGNED NOT NULL,
  `candidate_count` INT UNSIGNED NOT NULL DEFAULT 0,
  `active_count` INT UNSIGNED NOT NULL DEFAULT 1,
  `enabled` TINYINT UNSIGNED NOT NULL DEFAULT 1,
  `comment` VARCHAR(255) NOT NULL DEFAULT '',
  PRIMARY KEY (`region_id`),
  UNIQUE KEY `uk_region_name` (`region_name`),
  UNIQUE KEY `uk_box_entry` (`box_entry`),
  UNIQUE KEY `uk_pool_entry` (`pool_entry`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 지역 룬문자 매핑 테이블

```sql
CREATE TABLE IF NOT EXISTS `hero_stone_rune_box_loot` (
  `region_id` INT UNSIGNED NOT NULL,
  `location_id` INT UNSIGNED NOT NULL,
  `rune_item_entry` INT UNSIGNED NOT NULL,
  `weight` INT UNSIGNED NOT NULL DEFAULT 100,
  `enabled` TINYINT UNSIGNED NOT NULL DEFAULT 1,
  PRIMARY KEY (`region_id`, `location_id`),
  KEY `idx_rune_item_entry` (`rune_item_entry`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 박스 클릭 로그 테이블

```sql
CREATE TABLE IF NOT EXISTS `character_hero_stone_rune_box_log` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `account_id` INT UNSIGNED NOT NULL,
  `character_guid` INT UNSIGNED NOT NULL,
  `region_id` INT UNSIGNED NOT NULL,
  `box_guid` INT UNSIGNED NOT NULL,
  `rune_item_entry` INT UNSIGNED NOT NULL DEFAULT 0,
  `result` VARCHAR(32) NOT NULL,
  `created_at` TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_account_id` (`account_id`),
  KEY `idx_character_guid` (`character_guid`),
  KEY `idx_region_id` (`region_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

## 드랍률 정책

박스를 클릭했다고 항상 룬문자가 나오는 구조는 권장하지 않습니다. 발견 보상은 주되, 룬문자 획득은 확률로 처리하는 것이 좋습니다.

권장 기본값:

| 상황 | 룬문자 획득 확률 |
|---|---:|
| 일반 지역 박스 | 20% |
| 도시/대도시 박스 | 10% |
| 인던/공격대 연계 지역 | 15% |
| 희귀/고가치 지역 | 5% ~ 10% |

실패 시 메시지:

> 룬문자의 흔적은 남아 있지만, 아직 완전한 문자는 발견하지 못했습니다.

성공 시 메시지:

> 희미한 룬문자 상자에서 새로운 룬문자를 발견했습니다.

## 중복 처리

지급 후보에서 아래 항목은 제외한다.

1. 계정 기준 이미 해금된 룬문자
2. 구독 중인 계정
3. 비활성화된 지역 또는 룬문자

현재 가방에 이미 같은 룬문자 아이템을 보유 중인 경우는 제외하지 않는다. 중복 보유는 허용한다.

해당 지역의 모든 룬문자를 이미 해금했다면 다음 메시지를 출력한다.

> 이 지역에서 발견할 수 있는 룬문자는 이미 모두 영웅석에 새겨져 있습니다.

구독자는 다음 메시지를 출력한다.

> 구독 중에는 모든 룬문자가 새겨진 상태로 이용되므로 룬문자 상자를 사용할 수 없습니다.

## 구현 단계

### 1단계: 데이터 확정

1. `hero_stone_rune_items_by_map_ko.md` 기준으로 66개 지역 그룹을 확정한다.
2. 지역별 룬문자 수가 231개로 맞는지 다시 검산한다.
3. 지역명 매핑 오류가 있는지 수동 검토한다.

### 2단계: 테이블 추가

1. `hero_stone_rune_box_region` 생성
2. `hero_stone_rune_box_loot` 생성
3. `character_hero_stone_rune_box_log` 생성

### 3단계: 박스 템플릿 생성

1. 66개 지역별 `gameobject_template` 생성
2. displayId는 눈에 띄는 상자 또는 룬문자 석판 형태 사용
3. 이름은 `희미한 룬문자 상자 - 지역명` 형식 사용

### 4단계: 후보 좌표 생성

1. 기존 순간이동 좌표 주변을 기준으로 후보 좌표 생성
2. 지역별 후보 박스 수만큼 `gameobject` 추가
3. 후보 좌표는 반드시 적용 전 미리보기 표로 검토

### 5단계: Pool 적용

1. 지역별 `pool_template` 생성
2. `max_limit`을 활성 박스 수로 설정
3. 후보 박스를 `pool_gameobject`에 연결

### 6단계: 클릭 스크립트 구현

1. 박스 클릭 이벤트 등록
2. 클릭 시 가십 메뉴 표시
3. 유저가 확인 버튼 선택 시 박스 entry로 지역 조회
4. 지역 룬문자 후보 조회
5. 계정 해금/구독 여부 확인
6. 확률 판정
7. 성공 시 룬문자 지급
8. 로그 기록

### 7단계: 테스트

1. 여명의 설원처럼 룬문자 1개 지역으로 먼저 테스트
2. 가시덤불 골짜기처럼 여러 룬문자가 묶인 지역 테스트
3. 북풍의 땅, 얼음왕관처럼 룬문자 수가 많은 지역 테스트
4. 구독자, 이미 해금한 계정, 가방 보유 상태 테스트

## 결론

현재 데이터 기준으로 룬문자 총 231개는 정상입니다.

구현은 지도별 66개 박스 그룹을 만들고, 후보 박스 315개 중 112개만 pool로 활성화하는 방식이 적합합니다.

드랍은 DB loot로 직접 처리하지 말고 Lua 또는 C++에서 가십 메뉴를 통해 지급 판정을 처리하는 것이 안전합니다. 그래야 계정 해금 상태, 구독 상태, 안내 메시지, 로그 기록을 모두 제어할 수 있습니다.

중복 보유는 허용하지만, 이미 계정에 새겨진 룬문자는 지급하지 않는 정책을 유지합니다.
